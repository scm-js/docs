Getting the files

The recommended source is your own StarCraft installation. Blizzard's free map editor download is the fallback for anyone without one. Both are offered by the Game Data dialog on first use and by Help ▸ Game Data… afterwards; the installing guide walks through it.

Source What you can do with it
A StarCraft: Remastered installation Edit, with classic or Remastered graphics; test and play maps; watch replays
A classic StarCraft (1.16) installation Edit, with classic graphics; test and play maps; watch replays
Blizzard's map editor download Edit, with classic graphics; watch replays

The map editor download carries the whole game's files, but it is a map editor's download, not the game. A copy made from it is enough to edit maps and watch replays. Testing a map or playing one, in the game or on the site's play page, needs StarCraft installed.

  • A classic installation has two archives, StarDat.mpq and BrooDat.mpq, with a patch_rt.mpq beside them that is applied over both, as the game applies it. Brood War's archive is required: its unit table is the layout the editor reads, and the Ice, Desert and Twilight tilesets exist only there.
  • A Remastered installation has no .mpq archives. The editor reads the same files out of its Data folder instead, along with Remastered's own pictures; see StarCraft: Remastered.
  • Blizzard's map editor download is a 101 MB zip carrying both archives and a patch_rt.mpq. With that applied, they give the same files a 1.16.1 installation does. The editor fetches only those three members, 83 MB, through a small forwarder at gamedata.scmjs.dev, because a web page cannot read Blizzard's download server directly. The forwarder stores nothing.

Either way the copy is made on your machine, in a background thread in the browser and in the app's own process on the desktop, so it happens once. Open maps pick the graphics up as they arrive.

Where it looks#

The editor settles on one source of game data when it starts, in this order:

  1. A data set you chose. When a data set other than the game's own is selected, its stored copy is asked for first. If that copy is gone, the editor says so and continues with the game's own files.
  2. Bundled with the build. A source build that ran npm run extract serves the files from its own folder. The desktop app serves its own copy the same way.
  3. A copy kept in the browser. An earlier install left the files in the browser's private storage for the site. The copy survives reloads and browser restarts. A browser with no such storage holds the files for the session only.
  4. The desktop app's search. The desktop app looks next to the app itself (so the two archives dropped beside it are found), in its own data folder, in SCM_DATA_DIR or STARCRAFT_DIR from the environment, in the usual install locations (C:\Program Files (x86)\StarCraft, /Applications/StarCraft, a Wine prefix on Linux), and in ~/StarCraft and ~/Games/StarCraft. The first folder with the archives or a Remastered installation is copied into the app's data folder, which is then step 2. Someone whose game is where the installer put it never sees a dialog.
  5. Nothing. The editor runs without graphics and opens the Game Data dialog.

Nothing is ever fetched from an address you did not name.

scmjs.dev/editor, the nightly at scmjs.dev/nightly and the play page at scmjs.dev/play share one copy, so the game is installed once for all three. The page scmjs.dev/editor/data lists every copy the browser holds: what it is, where it came from, how many files and how large, and when it was made.

Removing a copy#

Remove copy in Help ▸ Game Data… deletes the stored copy. The editor then goes back to whatever step of the search above it would have reached without it, which in the browser is the dialog's first page again.
