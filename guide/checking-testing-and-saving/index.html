Checking, testing and saving

Before a map is played, it can be checked for common mistakes, tried in the game, and saved in the form you want to release.

Check Map#

Tools ▸ Check Map… looks for what the game would refuse or silently drop. A map with no triggers is judged as a melee map and one with triggers as a scenario, since that is how each is played.

  • The file: missing sections, and any section whose length the game does not accept, with what the player would see (Invalid Scenario in the map list, Error loading scenario file as a game starts, in every game type or only in Use Map Settings, a briefing that does not play); a revision the game does not know; a map side longer than 256; a Brood War tileset on a revision without Brood War, and an Installation map with no triggers, which the game plays only as Use Map Settings. A verification table (VCOD) that fails the game's check for the map's players is reported, and Save puts StarEdit's table, which always passes, in its place.
  • Players and start locations: a player without a start location, which eliminates them at once in melee and only moves the opening view in a scenario; several start locations for one player (the game uses the last); start locations for Players 9–12; player colours on a StarCraft 1.00 or Hybrid map, which StarCraft 1.16.1 does not show, and colours past the twelve the game takes from the palette.
  • Units the game leaves out: in a scenario, the placed units of a player whose race is User Selectable (the game removes them and hands out melee start units instead) and of a slot that is not in the game; in melee, everything but start locations and Player 12's resources and critters; ground units standing where they cannot walk; resource amounts past 65,535, which the game keeps as 16 bits; more than 1700 units, or units off the map.
  • Text: a string table past STR's 64 KB of offsets (Save refuses it), or a Remastered string table in a revision that does not read it; a map name or force name longer than the lobby shows (Remastered counts the name's bytes as UTF-8, where a Korean syllable takes three), and a description longer than StarCraft 1.16.1 shows; UTF-8 text a 1.16.1 player sees garbled; Windows-1252 text Remastered shows as Korean; a custom unit name on a type that uses the default settings (the game ignores it).
  • Triggers: a missing or moved Anywhere location; locations that are unused or not set at all (a location action without one does nothing); strings that do not exist; unit and player values the game does not have; condition and action types it does not have, which crash StarCraft 1.16.1 (Remastered takes such a condition as false and skips such an action); Create Unit, Set Resources and Set Score for Players 9–12, which do nothing; Create Unit of a unit class or of a type StarEdit's palette leaves out, which makes nothing; a trigger ticked twice for one player, which runs twice; a trigger with flag 0x02, which defeats every other player each time its actions run; Mission Briefing in a trigger, and a briefing that does not start with it; AI scripts a trigger owned only by people, rescuable or neutral slots cannot run; Play WAV actions with no file in the map, and Ogg sounds, which only Remastered plays; switches tested for Set but never set.
  • Terrain: tiles with bit 15 set, which the game files as a creep flag, though in play such a tile shows no creep and takes no Zerg building; tiles from groups the tileset does not have; tiles only Remastered's tilesets have; a missing or outdated isometric record.

A map with triggers gets three more checks:

  • a human player with no way to win or lose: no Victory, and no Defeat or win for another player (in a scenario nobody wins or loses unless a trigger says so);
  • no Set Mission Objectives;
  • with hyper triggers present, a Wait or a person's Transmission in another trigger of the same player, which fights them for the player's one wait slot (see Waits in the trigger reference).

Double-click an issue to go to it. The same check runs inside the Save dialog.

Test Map#

Tools ▸ Test Map (Ctrl+F5) hands the map to the game. The game cannot open a map from the outside, so the editor writes it into a scmJS folder under the game's Maps folder, where Single Player ▸ Custom Game lists it.

  • The desktop app finds the installation (or takes a folder you pick) and starts the game as well.
  • Chrome and Edge write the map into a folder you pick once. Start the game yourself and open the map under Single Player ▸ Custom Game.
  • Firefox and Safari download the map; move it into the game's Maps folder.

Tools ▸ Test Map Settings… opens the dialog to change the folder and whether the game starts.

Test Map in Browser. In the editor at scmjs.dev, Tools ▸ Test Map in Browser opens the map on the site's play page, scmjs.dev/play, which runs the game in a browser tab. The map goes straight from the editor's tab to that one, and testing again sends the new version to the same tab. The game runs from your own StarCraft files: the first time, the play page asks for the folder StarCraft is installed in. Blizzard's map editor download is not enough for it.

How the map is played is set under Edit ▸ Preferences ▸ Plugins ▸ scm-sim:

  • Game type. From the map (the default) plays with the map's own settings when it has computer players or units placed beyond the start locations, and as a melee game otherwise. Use Map Settings and Melee always play that way. Choose on the play page opens the map on the play page's setup screen, which lists the map's forces and slots as the game's own lobby does, and nothing starts until you press Start Game.
  • Your race, your slot for Use Map Settings (the first open one, or a player you name), and for melee the number of computers and their race. Where the map fixes a slot's race or has fewer places, the map's settings win.

Note. Test Map in Browser comes with the scm-sim plugin and appears only in the editor at scmjs.dev, not in the desktop app or an editor hosted elsewhere.

Saving#

Ctrl+S writes the map back where it came from.

  • Chrome, Edge and the desktop app keep a handle to the file you opened, so Save writes in place once the browser has asked for permission.
  • Firefox and Safari give the editor a file's contents but no way to write it back, so every save is a download, and the notice at the bottom right says so.

Save As (Ctrl+Shift+S) and Save Copy As… open the Save dialog; a copy is written without the open map changing its name or file.

The Save dialog asks for a file name, a format and what to keep. Everything else is folded away underneath and can be left alone:

  • Format: .scx (Brood War), .scm (original StarCraft), or a bare .chk, the scenario alone with no archive around it.
  • What to keep: Everything writes the whole file, so any editor can open it with nothing lost. Smallest that plays leaves out the parts only an editor reads (the isometric record, the editor's copies of the player settings and so on) and compresses the archive as StarEdit does; the map plays the same, but an editor opening the file later has less to work with. Custom shows each of those parts with its own tick. The map in the editor is not changed either way.
  • Archive (folded): the compression, StarEdit's encryption tick, and the other files in the archive. PKWARE is what StarEdit writes, and every StarCraft version reads it; zlib is smaller but only Remastered reads it (StarCraft 1.16.1 cannot open such a map); none is the largest and readable by anything. A map keeps the compression it was opened with. The sounds and the files plugins keep in the archive each have a tick, so a copy for release can leave them out. Files in the archive the editor cannot name — common in protected maps — are kept exactly as they were, and the fold says how many there are.
  • Sections (folded): every section the file will hold, with its size and whether it changed, was left out or was merged.

If Check Map finds problems, the dialog says how many beside a button that opens it; the map saves either way. The options confirmed here are what Ctrl+S reuses for that map from then on.

The file a save replaces is kept, so a bad save can be undone:

  • The desktop app copies the old file to a .bak beside it first (Lagoon.scx to Lagoon.scx.bak, replacing an older .bak). If the .bak cannot be written (a read-only folder, say), the save still goes through, a notice says why, and the old file goes to Previous Versions instead.
  • Chrome and Edge cannot put a file beside another, so the version replaced is kept in the browser's storage, the last three of each file name. File ▸ Previous Versions… lists them: Open puts one in its own tab with "(previous)" added to its name, and Save As writes it out as it was.
  • Firefox and Safari download every save and replace nothing, so there is nothing to keep.

Preferences ▸ General ▸ Saving turns this off.

Maps built on save. A map with a TrigScript program is built by TrigScript as the file is written. The file you save is the one the game plays, and it carries the map as you see it in the editor inside, which is what comes back when you open it again. A notice shows while the build runs, with a button to save without waiting for it. If the build fails, the map is still saved and the notice says what went wrong; the file lacks the built part until a later save succeeds. Test Map builds the same way, and stops on a failure instead.

Save to scmjs.dev…, under File and under Account, keeps a copy of the map on your scmjs.dev account as a numbered revision with a note. It does not change where Ctrl+S writes. See Keeping maps on scmjs.dev.

Recovery copies#

While a map has unsaved changes, the editor keeps a copy of it in the browser's storage (the app's own storage in the desktop app): every two minutes, and whenever the editor goes to the background — another tab, the window minimised. The copy is removed as soon as the map is saved or closed, so a copy only survives when the editor closed with work unsaved: a crash, a closed tab, a power cut.

At the next start the Recover Maps dialog lists what was left, with the map's name, its file, its size and when it was copied. Restore opens the map in its own tab with its changes unsaved, under its old file name, so Ctrl+S writes back to the same file (after the browser asks again for permission). Later keeps the copies for the next start, and File ▸ Recover Maps… lists them at any time. Maps still open in another tab or window are never listed there.

Quitting the desktop app and answering Don't Save removes the copies. A copy only covers changes up to the moment it was made, and it lives in this browser: it is not a backup of the file, and clearing the site's data removes it. Preferences ▸ General ▸ Recovery turns the copies off or changes how often they are made.

Export an image#

File ▸ Export ▸ Image (.png)… renders the whole map to a PNG, with one setting that decides what the picture is: at 32 pixels per tile it is the full game art, at 8 or 16 the same smaller, at 4 and 2 the average tile colours with units as minimap dots, and at 1 pixel per tile it is the game's minimap. Units, locations, fog and the grid are each a tick.

To show how a map was made rather than how it ended up, the Timelapse plugin (Plugins ▸ Browse Plugins…) records the map one change at a time and exports the recording as a GIF or a WebM video; see Plugins.

Tools ▸ Statistics… counts what the map holds — units per player, resources, doodads, triggers, strings — and Ctrl+F finds a unit, location, sprite, string or trigger by name.
