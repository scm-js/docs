Keyboard and preferences

Press F1 for a list of every shortcut. These are the ones the editor starts with; any of the commands can be given other keys on Preferences ▸ Hotkeys:

Keys
T D U S L F C switch layer
[ ] brush size
M symmetry on / off
Alt+click pick what is under the cursor
Ctrl+Z / Ctrl+Y undo / redo
Del / Esc delete selection / stop placing
Ctrl+O, Ctrl+S, Ctrl+N open, save, new
Ctrl+Shift+S save as
Ctrl+T Trigger Editor
Ctrl+Shift+T Text Trigger Editor (when TrigEdit is on)
Ctrl+Shift+A AI assistant (with your Anthropic key)
Ctrl+F find
Ctrl+A select all on the layer
Ctrl+G grid
Ctrl+0, Ctrl+Shift+0 100%, zoom to fit
Alt+Enter map properties
Ctrl+F5 test map
Ctrl+, preferences
Ctrl+Tab, Ctrl+Shift+Tab next / previous open map (desktop app)
Ctrl+W close map (desktop app)

Preferences (Ctrl+,) are kept in the browser. Nothing is written until OK or Apply, and Reset to defaults puts every page back. The pages down the left:

General

  • Language: English or Korean. The default follows the browser's, and a change applies at once. A map's own text is never translated.
  • Startup: the splash screen; whether to reopen the last map (the desktop app does it straight away; a browser that has to ask before reading the file again offers it in a notice); how many recent files to keep. In the desktop app, whether to check for updates at startup, and whether to include nightly builds.
  • Maps: whether each map opens in its own tab, and whether to ask before closing or replacing a map with unsaved changes.
  • New scenario: the tileset, size and revision a new map starts with.
  • Saving: what the Save dialog starts from (how the file was opened, Everything or Smallest), the compression for a map with no file yet, and whether a save keeps the file it replaces (a .bak, or a previous version in a browser).
  • Recovery: whether to keep recovery copies of unsaved maps, and how often.
  • Privacy (the editor at scmjs.dev only): whether to count which parts of the editor are used. It is on unless you turn it off. When you use a feature, the editor sends its name and a few words about it, such as which dialog opened or which layer an edit was on. When something goes wrong, it sends where in the editor's code the error happened (the file, line and function) and whether the browser was translating the page, but never the error's message. It never sends the map, its name, a file name or anything you typed, and nothing that identifies you. Turning it off also stops the visit count for this browser, and the site's privacy page has the same switch and the details. The desktop app and copies of the editor hosted elsewhere count nothing.

Editing: the grid's spacing, colour and style, and what snaps to it (View ▸ Grid Settings… opens this page); what the palettes start on — the owner of placed units, the brush size, the size of a new location; and how many undo levels each map keeps.

View: whether the mouse wheel scrolls (Ctrl+wheel zooms) or zooms, and whether a wheel zoom keeps the tile under the pointer in place; whether water and units animate and how fast; whether the map starts out drawn with Remastered's graphics; which cells the status bar shows; and whether string previews follow Remastered's colour rule or 1.16.1's.

Testing: Test Map's folder, and in the desktop app whether the game starts after the map is written.

Plugins: what to do when an installed plugin has a newer version (tell you, do nothing, or install it — see docs/plugins.md), and each plugin's own settings page.

Storage: where the game data comes from, and everything the editor keeps in the browser, one row per setting or cache, with a plugin's own data under its name. Each row can be cleared on its own, or Clear all data throws the lot away. Maps are not part of that list and are not touched by it. The recovery copies and the previous versions of saved files have their own lines. Export writes the settings, the plugins' included, to one file, and Import reads such a file into another browser or machine; caches and the recent files stay behind.

Hotkeys: every command and its keys.

  • + on a row waits for the next keys you press and adds them (Esc stops waiting); the × on a key removes it. A command can have several keys or none.
  • Keys used by two commands, or by a command and a plugin, are marked. A plugin's keys are tried first; between two commands, the one higher in the list wins.
  • Delete, Esc, the arrows, Tab, Enter, Space and F11 keep their own jobs and cannot be given to a command.
  • A plain key such as T never fires while you type in a text box, and most Ctrl shortcuts leave a text box's own undo, clipboard and select-all alone.
  • The browser keeps Ctrl+Tab and Ctrl+W for its own tabs, so Next Map and Close Map start with no keys there; give them others if you want them.

The placement options, the panels and the recent files are remembered too.

What's new#

Help ▸ What's New… lists what changed in each release, newest first, with the release you are running open and the older ones folded below it. The part written for plugin authors is folded as well. The notes come with the editor, so the list works offline and always matches the version in front of you; a nightly build shows the notes of the last release. The version line in Help ▸ About scmJS… opens the same list.

The first time you start a release with new notes, a notice says the editor has been updated and offers the list. It appears once per release. The notes are written in English.

In the desktop app, Help ▸ Check for Updates… looks for a newer version.
