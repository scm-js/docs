Triggers

Triggers turn a map into a scenario: when these conditions hold, for these players, do these actions. A Use Map Settings map is built from them. A melee game ignores the map's triggers and applies its own rules, so a melee map needs none. (Blizzard's melee maps carry the three standard ones — defeat, victory, starting resources — for anyone who plays them as Use Map Settings.)

Several editors work on the same list of triggers, and you can switch between them freely:

  • The Trigger Editor (Ctrl+T): StarEdit's form.
  • The Text Trigger Editor: the triggers as text in SCMDraft 2's syntax. It is a plugin, installed but off.
  • TrigScript: triggers written as code. See TrigScript.
  • Magenta (Plugins ▸ Browse Plugins…): every trigger as a sentence, with a catalogue of StarCraft: Remastered EUD conditions and actions.

Mission briefings have an editor of their own. The trigger reference has a page for every condition and action.

To see how a map's triggers fit together, the Trigger Map plugin (Plugins ▸ Browse Plugins…) draws them as a graph: which triggers set a switch, a death counter or a location and which ones read it, with a list of switches nothing sets, counters nothing reads and triggers that never run.

The Trigger Editor#

Ctrl+T, or Triggers ▸ Trigger Editor…. A player filter on the left, the trigger list in the middle, and for the selected trigger its players, up to 16 conditions and up to 64 actions.

The Players tab offers the owners the game hands triggers to: Players 1–8, All Players and the four forces. A trigger ticked for nothing else never runs, so the other groups (Player 9–12, Current Player, Foes, Allies and the rest, which are arguments rather than owners) only show when a trigger already has one ticked, to be cleared.

Every condition and action the game has is there, except that Mission Briefing is offered only in briefings, since in a trigger it is never true. Each argument gets a widget of its kind — a player pick, a unit type list, a location list, a number, a text box with the colour codes — and any value the lists do not include can still be typed as a raw number, which is how EUD values and unusual unit ids get in. An item can be disabled without deleting it; a disabled one is kept in the file and skipped by the game. Preserve trigger is the flag that keeps a trigger firing more than once.

A new Create Unit, Create Unit with Properties or Set Deaths starts on Terran Marine rather than Any unit: the game creates nothing for a unit class, and Set Deaths on Any unit writes nothing. A Create Unit amount of 0 makes one unit, where elsewhere 0 means all of them. The unit list of the two Create Unit actions holds only what the game will create, the units of StarEdit's palette; larvae, eggs, traps, doors and the like are left out, because the game refuses them.

The Text Trigger Editor#

The same triggers as text, in SCMDraft 2's TrigEdit syntax, so text from SCMDraft pastes in and text from here pastes back out. Compile checks it and reports the first line that does not parse.

It is the TrigEdit plugin, installed but starting off: tick it on in Plugins ▸ Manage Plugins…, and Triggers ▸ Text Trigger Editor… and its Ctrl+Shift+T appear.

A leading ; disables a line, and a Flags: block carries the trigger flags SCMDraft has no syntax for. The Briefing switch at the top edits the mission briefing in the same syntax.

Mission briefings#

Triggers ▸ Mission Briefing Editor… (also Scenario ▸ Mission Briefing…) is the same form over the briefing actions: text, portraits, transmissions and the pauses between them, one briefing per player. The layout matches the briefings on Blizzard's own multiplayer maps.

Unit properties slots#

Triggers ▸ Unit Properties Slots… is the table behind the Create Unit with Properties action: 64 slots, each the hit points, shields and energy (as percentages), resources, hangar count and special states a trigger applies to the units it creates. The action's argument lists the slots by what they set and opens this editor on one.

EUD#

For EUD work, the player pick next to a Deaths condition or Set Deaths action has an EPD box: type a memory address and it becomes the player value that reaches it through the deaths table, and a raw value shows which address it reaches. Check Map points out the raw values so they are not mistaken for errors.

For named reads and writes of the game (a unit's hit points, a player's minerals), use a TrigScript program or Magenta. Both make maps that play on StarCraft: Remastered only.

Importing, exporting and checking triggers#

File ▸ Import and File ▸ Export (also Triggers ▸ Import Triggers… and Export Triggers…) carry triggers as .trg files, SCMDraft's format, or as text. An import can be added to the map's triggers or replace them. A .trg holds string numbers rather than text, so it fits only a copy of the same map; text works between maps.

Triggers ▸ Validate Triggers is Check Map limited to the triggers.
