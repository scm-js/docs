Getting started

You need Node.js 22.18 or newer (the extraction scripts import TypeScript directly through Node's type stripping) and git.

git clone https://github.com/scm-js/scm-js
cd scm-js
npm install
npm run dev            # http://localhost:5173

The first npm run dev or npm run build needs a network connection: a predev / prebuild hook fetches the default plugins at their pinned versions into the gitignored plugins/ folder, where the build compiles them in (see Defaults and vendoring). After that it works offline. The same hook reports what game data is on disk, and warns rather than fails when there is none.

Game data. The editor draws with StarCraft's own graphics, which are never committed. Without them terrain is flat colours and units are markers, and everything else works. There are two ways to get them into a source build:

  • Help ▸ Game Data… in the running dev editor. Point it at your StarCraft folder, the classic game (1.16) or StarCraft: Remastered. This is the recommended way, and the only one for Remastered: the copy goes into the browser's storage, as it does for any user.
  • npm run extract reads StarDat.mpq and BrooDat.mpq from a classic installation (it finds them on its own, or takes --from <folder>) and writes the files into public/. It does not read Remastered's files.

game-data.md has the details. No build, container image or hosted site carries the data or an address to fetch it from; ATTRIBUTION.md has the terms.

Dev deep links#

Query parameters jump straight to a UI state, which is the fastest way to work on a screen or take a screenshot:

/?nosplash                        skip the splash
/?nosplash&layer=units            select a layer: terrain, doodads, units, sprites, locations, fog, clipboard
/?nosplash&dialog=playerSettings  open a dialog by id; repeatable
/?nosplash&dialog=preferences&page=editing   open a dialog at one of its pages
/?nosplash&zoom=0.5&tileset=ice   zoom level and tileset
/?nosplash&mode=tile              terrain palette mode: isom, rect, tile
/?nosplash&layer=fog&fogPlayer=3  view and paint one player's fog

An unknown layer or dialog id is reported in the console with the list of valid ones. React's "Components" performance track is off in development because it slows mounting badly; set VITE_REACT_TRACKS=1 to turn it on when profiling renders.

With the game engine beside it#

Tools ▸ Test Map in Browser, and the replay analysis other plugins use, come from the scm-sim plugin. The plugin holds no engine: it opens the play page, which has to be on the editor's own origin at /play/, as it is on scmjs.dev. The play page is built from the scm-sim engine repository, which is not public, so without it these features do not work in a local build. With a checkout of it, run both dev servers and put one origin in front of them:

SCMJS_BASE=/editor/ npm run dev -- --port 5173   # this repository
npm run dev:web                                   # in scm-sim, port 5174
npm run dev:site                                  # this repository: http://localhost:5180/editor/

Both dev servers keep their own hot reload. DEV_SITE_PORT, DEV_SITE_EDITOR and DEV_SITE_SIM change the three ports.
