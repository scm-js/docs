Getting started

There are three ways to install scmjs. Each gives you the same command at the same version, so pick the one that suits your computer:

  • A package manager: Homebrew, Scoop or winget. Nothing else needs installing, and it updates with the rest of your software.
  • npm, if you already have Node.js 22.12 or newer.
  • A download from the releases page, if you use neither.

Installing#

With Homebrew, on macOS or Linux:

brew install scm-js/tap/scmjs

With Scoop or winget, on Windows:

scoop bucket add scm-js https://github.com/scm-js/scoop-bucket
scoop install scmjs

winget install scm-js.scmjs

winget does not list scmjs yet: its first version is waiting for review. Until it does, use Scoop or the download.

With npm:

npm install -g @scm-js/cli

To try it without installing anything, run it through npx, which fetches it the first time. Every command in this guide then starts with npx @scm-js/cli instead of scmjs:

npx @scm-js/cli info "(2)Ridge.scx"

Without a package manager or Node, download the program.

Then check it works. scmjs about prints the version and how this copy was installed:

scmjs about

However it is installed, scmjs runs every command, and the package manager and download versions bring their own copy of Node. The one thing they leave out is TypeScript, which map build and plugins written in TypeScript need. Install it with npm, in the map's project (npm install typescript@6) or globally; scmjs looks in both places, and scmjs doctor says whether it found it. A map's script compiles with TypeScript 6. TypeScript 7 is a different kind of program that scmjs cannot drive, and TypeScript 5 refuses the settings a script is checked with, so either is passed over and doctor says "too new" or "too old". The extension for Claude Desktop carries its own copy.

A first look#

Five commands show most of what scmjs is for. They are run here on ums.scx, a small scenario with three triggers.

scmjs info says what a file holds, whether it is a map, a replay or a built bot:

$ scmjs info ums.scx
Test Scenario
Triggers, a briefing, locations, a sound and unit settings.

  Map        64 × 64 · Badlands · Brood War 1.04
  File       ums.scx · 5.9 KB
  Players    2 slots used · 2 start locations
  Units      21 (14 neutral)
  Resources  12 mineral fields (18,000) · 2 geysers (10,000)
  Triggers   3 (3 conditions, 8 actions) · briefing 1 trigger
  Objects    3 locations · 0 doodads · 2 sprites
  Strings    20 of 20 · 1 sound
  Check      ▲ 1 warning
  …

scmjs map check runs the editor's Check Map over as many maps as you name. It exits with 1 when a map has errors, so a build can stop on it:

$ scmjs map check ums.scx melee.scx
ums.scx  ▲ 1 warning
  ▲ Nothing makes Player 1 lose: no Defeat, and no Victory or Draw for another player. A scenario
    does not end when a player's units are gone. · Triggers

melee.scx  ✔ no problems

✔ 2 maps checked, none failed

scmjs map preview draws the map in the terminal, or writes a PNG, with the graphics of your own copy of StarCraft:

scmjs map preview ums.scx
scmjs map preview ums.scx --out ums.png

scmjs map diff says what changed between two versions of a map, in a map maker's terms:

$ scmjs map diff ums.scx ums-2.scx
ums.scx → ums-2.scx

Map
  ~ Name           Test Scenario → Test Scenario 2

Strings ~1
  ~ 1  Test Scenario → Test Scenario 2

Sections
  ~ STR   355 B → 357 B

scmjs map trace runs the map's triggers in the game itself, with nobody playing, and says which fired and which never did:

$ scmjs map trace ums.scx
✔ ums.scx: 3 triggers · 2,400 frames (1:40 of play) · 78 passes · 1 fired · 2 never · 2.3 s

  #  Fired  First  Last  Players  Trigger
  1  1      2      2     P1       Always() → Display Text Message(Always Display, "Hold the base."); …
  2  0      –      –     P1       Bring("Player 1", "Terran Marine", "Middle", At least, 1) → …
  3  0      –      –     P1       Switch("Alarm raised", set) → Victory()

  Never fired (2 of 3)
  ▸ #2  Bring("Player 1", "Terran Marine", "Middle", At least, 1) → …
      Bring (condition 1) said no last, at frame 2,389
  ▸ #3  Switch("Alarm raised", set) → Victory()
      Switch (condition 1) said no last, at frame 2,389

The first, second and fourth need nothing but the command. The picture and the trace read your copy of StarCraft, and the trace fetches the game engine the first time (Commands that need StarCraft).

Cheat sheet#

scmjs info map.scx                              # what the map holds
scmjs map check maps/*.scx --strict             # fail on errors and warnings
scmjs map check maps/*.scx --baseline --strict  # fail only on findings not in .scmjs-baseline.json
scmjs map preview map.scx --out map.png         # a picture
scmjs map find "Marine" maps/*.scx              # search
scmjs map triggers edit map.scx                 # triggers in your text editor
scmjs map open map.scx --live                   # in the editor, linked: commands change it there
scmjs map diff --rev HEAD~1 map.scx --picture   # what the last commit changed, and where
scmjs map log map.scx                           # the map's history, in the map's terms
scmjs map blame map.scx                         # who last changed each trigger
scmjs map generate "(2)Duel.scx" --seed 7       # a melee map to play
scmjs map terrain map.scx                       # the terrains, and the map as a grid of letters
scmjs map edit map.scx --edits edits.json       # paint terrain, place doodads and units from a list
scmjs map analyze map.scx --out layout.png      # starts, naturals, walks and chokes, in a second
scmjs map balance map.scx --bots mybot.scmbot   # is every start fair? games from each
scmjs map optimize map.scx --dry-run            # what would make the map smaller
scmjs map trace map.scx                         # which triggers fire in the game
scmjs map test map.scx                          # run map.tests.json in the game
scmjs map test map.scx --clips                  # and a GIF of each failed scenario's end
scmjs map test map.scx --show                   # and what each game did: lines shown, triggers fired
scmjs map script import map.scx script/         # put a TrigScript script's files into the map
scmjs map trace --replay bug.rep --order        # which triggers fired in a played game, and when
scmjs map coverage map.scx replays/             # which triggers never fired in any of those games
scmjs replay watch game.rep                     # a replay in the terminal
scmjs map heatmap map.scx replays/ --out h.png  # where units died in those games
scmjs replay export game.rep --to 0:30          # its first half minute, as game.webm
scmjs map share map.scx --qr                    # a link, and a code for a phone
scmjs library                                   # your maps and replays on scmjs.dev, with their links
scmjs replay info https://scmjs.dev/replay/…    # any command reads a link as a file
scmjs replay sync --watch                       # each game's replay to your account as it is saved
scmjs init                                      # this folder of maps, ready for git
scmjs map unpack map.scx --text                 # the map as text files, to keep in git
scmjs mod unpack MyMod.mpq mymod                # a mod as text and pictures; mod pack puts it back
scmjs bot run mybot.js map.scx                  # a bot against the game's computers

The commands#

scmjs on its own, or scmjs --help, prints the overview pictured at the top of this guide. Most commands sit under a noun: map, replay, mod, plugin, bot, library and account. scmjs map (or scmjs map --help) lists the map commands, grouped by task much as this guide's chapters are, and every command has its own --help with its options and examples; scmjs help map diff is the same as scmjs map diff --help. The overview's last group names the commands it has no row for: about, completion, init, login, logout and lsp. The command reference lists them all on one page.

A command that takes several files takes as many as you name, so a shell pattern works:

scmjs map check maps/*.scx

A file that cannot be read is reported and the others carry on. The Windows Command Prompt and PowerShell do not expand *.scx for a program, so there you name the files.
