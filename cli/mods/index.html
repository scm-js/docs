Mods

A mod is the game with other data: other tables, animation scripts, pictures, sounds, strings and AI. scmjs mod reads a mod as its makers ship it, unpacks it into a folder of text and pictures to edit and keep in git, checks it, compares two versions, packs it back into the MPQ the launchers load and hands it to the play page. The mods guide has the folder's form and how it works with PyMS, MPQDraft, FireGraft and samase; this section is the commands.

What a mod holds#

scmjs mod info "Cosmonarchy BW"
scmjs mod info MyMod.mpq "My Mod.exe" mymod.zip

says what a mod is: its files and their sizes by kind, its tables and which are wider than the game's (DatExtend's expanded .dat, GPTP's .datex), its scripts, the plugins and FireGraft files it carries (kept, never run), a self-executing exe's archive, the game it is for, and the mod's hash with the hash without its plugins beside it, the older hash of a mod that holds an operating system's files, and the races its mod.json names. It reads a folder (the game's paths at its root or in a folder under it), an .mpq, a self-executing .exe (MPQDraft's or FireGraft's patcher, read and never run) or a .zip. A copy of the game inside the folder, a folder that holds StarDat.mpq, is not the mod: its own archives and everything under its Maps folder are left out, and the command says so (which files). --json prints the same as data, the files left out as gameCopy.

A mod as a folder of text#

scmjs mod unpack MyMod.mpq mymod
scmjs mod pack mymod -o MyMod.mpq

mod unpack writes the tables as PyDAT's text, the string tables, iscript and AI as PyMS's text, the GRPs as PNG sheets (the units' sprite sheets and the uncompressed GRPs of the dialogs, score screens and icons alike) and the rest as they are, and mod.json. A file is written as text or a picture only when that packs back into the same bytes; anything else stays as it is under files/, and mod.json says which and why. mod pack puts the folder back into an MPQ (--compression zlib, pkware or none), or with --folder <out> into loose files in the game's paths. The same folder gives the same MPQ every time. scmjs mod new <folder> starts an empty one.

Checking and comparing mods#

scmjs mod check mymod
scmjs mod diff mymod
scmjs mod diff v1.mpq mymod
scmjs mod build mymod -o MyMod.mpq

mod check looks across the tables for what makes the game stop or draw nothing (a reference past its table, an image with no GRP, an image whose animation script is missing, a string past its table, a button set or requirement for something not there) and for what is probably a mistake (a weapon the mod added that no unit carries, a sound row with no file, units with one name). It exits 1 on an error. When the mod's files suggest races of its own and its mod.json names none, it says so in one line, which is a hint and fails nothing (Races a mod adds). mod diff reads as a changelog, "Terran Marine: ground weapon damage 6 → 7", against your copy of the game when given one mod. mod build checks, then packs, and stops on an error unless --force.

These commands read your copy of StarCraft when they find one, as the commands that need StarCraft do, for the game's own files under the mod; they work without it and say what they could not look at.

Playing a mod on the play page#

scmjs mod play mymod
scmjs mod play MyMod.mpq --map "(2)Ridge.scx"
scmjs mod play "Cosmonarchy BW" --map "(4)Exodus 1.0.scx" --bot cosmonarchy-example --race terran
scmjs mod play "Cosmonarchy BW" --map "(4)Exodus 1.0.scx" --bot mybot/out/mybot.scmbot --start

opens scmjs.dev/play in your browser and hands it every file of the mod, with its plugins and FireGraft files, and the mod's hash. The page keeps the files that differ from your copy of the game. Nothing is uploaded: the page keeps the mod in your browser. A mod with plugins or a FireGraft project is handed to the page at ?lift=live, the address where the page runs them. On the play page has what the page does with a mod once it has it.

--bot puts a community bot on the other side: one of the play page's bots by its key (cosmonarchy-example, mcrave, ualbertabot, example), or a .scmbot file of your own, which the page keeps as Options → Add a bot from a file… keeps one. --race is the bot's race where the map leaves it open: zerg, terran, protoss or random, or a race the mod's mod.json names, by its name or its number. The map is on the page's setup screen with the bot in the row beside yours, which says whether the bot was made for the mod, plays vanilla data, or was made for another; you press Start Game. --start starts the game at once instead. A mod with plugins plays the map with its own settings, as the engine's runners play it. The play page's own bots need a scmjs.dev account: the page asks you to sign in, and the command prints that it is waiting. The command prints what the page said and the bot's row:

Cosmonarchy BW: 7,769 files to hand over (and 9 plugins and FireGraft files) · 931.1 MB · hash ac3f86533e4b5a31
ℹ Opening the play page with Cosmonarchy BW in your browser
  If nothing opens, go to http://127.0.0.1:33525/58aab12d25f4b5a8cf293c11
ℹ The play page is ready: the mod is handed over
ℹ The play page is ready again: the mod is handed over again
✔ On the play page's setup screen: press Start Game
  Bot  Cosmonarchy Example — made for Cosmonarchy BW

The hand-over is the one map play uses: the command serves a page on 127.0.0.1, which opens the play page with ?handoff=1 and, each time that page says scmjs.ready or scmjs.play.ready, posts it:

{
  type: "scmjs.play",
  dataSet: {
    name: "My Mod",
    hash: "3f9a0c2e5b7d1146",          // 16 hex digits
    files: [{ path: "arr/weapons.dat", file: File }, …, { path: "plugins/gptp.qdp", file: File }],
  },
  map: Uint8Array,                      // with --map: the map's bytes
  name: "(2)Ridge.scx",                 // and its file name
  bot: { key: "cosmonarchy-example", race: 1 },   // with --bot: a key, or { file: File, name, race }
  setup: true,                          // with --bot and without --start: show the setup screen
}

race is 0 for zerg, 1 terran, 2 protoss and 6 random. With a bot, the message also says the kind of game: the map's own settings for a mod with plugins or a FireGraft project, otherwise the page's own guess.

path is the game's path in lower case with forward slashes; a plugin the mod carries is under plugins/ and a FireGraft file under firegraft/. A game file the page would not take as a loose file — one beside the game's folders or under plugins\ or firegraft\, as the members of Cosmonarchy's loader archive plugins\apply and firegraft\reqlist.txt are — goes in a small MPQ, scmjs-members.mpq, which the page opens as it opens a mod's own.

hash is the mod's hash, which the page works out again from the same files and arrives at. It is SHA-256 over one line name<TAB>sha256 of the file a file, sorted by name and joined with newlines; its first sixteen hex digits. A game file's name is the game's, lower case with backslashes (arr\weapons.dat); a plugin's is plugins\ and its file name, lower case (plugins\gptp.qdp); the FireGraft project's is its file name, lower case (cosmonarchy bw.fgp). FireGraft's database has no line, nor a plugin inside the mod's archive, which the page does not load, nor a file an operating system leaves in folders (desktop.ini, Thumbs.db, .DS_Store and the rest of that list), which is not handed over either. Without the plugins' lines it is the hash a page that runs none of them presents. A page that already keeps a mod with that hash can skip storing it again. The editor records the same hash for a data set made from the same files (see Game data). The page answers with scmjs.play.started, scmjs.play.shown or scmjs.taken, which end the wait, or scmjs.play.error with a message, which the command prints before it exits 1; scmjs.waiting and scmjs.play.waiting messages are printed as they come. With a bot, shown and started carry bot, the bot's row as the setup screen words it, and a bot the page has not got, or a map with no place for it, is an error in words. The command waits five minutes.

A mod in the game engine#

scmjs mod test mymod ridge.scx
scmjs map test ridge.scx --mod mymod
scmjs map trace ridge.scx --mod MyMod.mpq

mod test is map test with the mod's files laid over the game's; map test, map trace and map cost take --mod. These lay the mod's files only and run none of its plugins. A scenario with a bot on the other side is not there yet: map test plays the person's seat and the map's own computers. bot run and bot ladder take --mod too, and run the mod's plugins and FireGraft project beside the bot (a bot on a mod). With an engine older than the one a command needs, the command names the version it needs and stops.

A mod that changes animation scripts, pictures, overlays or the sound table makes the game read its startup data again before the game starts, and that opens every unit picture and overlay the image table names. With StarCraft: Remastered, the command reads those pictures out of your installation and lays them under the mod for the game, so such a mod runs on a Remastered copy as on a 1.16.1 one. They are the classic pictures, the same in both. The first line under the run says how many of the mod's files the game read and whether the startup data was read again without a missing file; --json has the same under mod.

A bot made for a mod#

scmjs mod header "Cosmonarchy BW"
scmjs mod header MyMod.mpq --out mybot --bot
scmjs mod header mymod --namespace MyMod --json

writes two files for a community bot made for the mod: <Mod>.h, C++ for a BWAPI bot built with scmbot, and <Mod>.ids.json. <Mod> is the mod's name made an identifier (Cosmonarchy_BW), or --namespace. The header is one namespace holding MOD_NAME and MOD_HASH (the mod's hash, the one mod info prints), then the mod's units in UnitTypes (each a BWAPI::UnitType made from its id), its weapons in WeaponTypes, upgrades in UpgradeTypes, technologies in TechTypes, and the same ids as plain numbers (constexpr int) in Ids::Units, Ids::Weapons, Ids::Upgrades and Ids::Techs:

#include "Cosmonarchy_BW.h"
namespace cosmo = Cosmonarchy_BW;
// …
if (unit->getType() == cosmo::UnitTypes::Terran_Ministry) unit->train(cosmo::UnitTypes::Terran_Mason);

The JSON is { "mod": { "name", "hash" }, "units": [{ "id", "name", "identifier" }], "weapons", "upgrades", "techs" }.

The names are the mod's, every one of them. A unit is named as the editor names it (the mod's unitnames.tbl, else stat_txt.tbl); a weapon, upgrade or technology by its table's label in the mod's strings, where a GPTP mod's rez\stat.txt fills the entries stat_txt.tbl leaves empty, and by the mod's own name list (arr\weapons.txt, upgrades.txt, techdata.txt, one line an entry, as Cosmonarchy ships them) when it has one for every entry. A name becomes an identifier by turning every run of other characters than letters, digits and _ into one _ (U-238 Shells is U_238_Shells, Terran Ogun (Worker Mode) is Terran_Ogun_Worker_Mode); one that starts with a digit, or is a C++ keyword or a Windows macro's name, gets a _ in front; one with no such characters left is its kind and id (Unit_612). When two entries of a kind have the same name, the first keeps it and each later one gets _ and its id (Floor_Hatch_385). Rows that name nothing are left out: an empty name, "None", "Reserved", "Unused", "*", and a data editor's "Extended Tech #54". The header says it was generated, from which mod and hash and on what day; run the command again rather than edit it.

With --bot, --out must be a bot's folder (one with scmbot.json): the two files go there and scmbot.json gains "mod": { "name", "hash" } (and "link" when the mod's mod.json has one), the rest of it as it was. The next scmbot build writes the mod into the .scmbot file, and bot run and bot ladder say whether the game's mod is the one the bot was made for (a bot on a mod). A small bot written this way for Cosmonarchy, which mines, builds Stockades and attacks with Mavericks, is in the scmbot repository's examples/cosmonarchy folder. On Cosmonarchy BW the header names 621 units, 330 weapons, 67 upgrades and 54 technologies. --starcraft names the copy of the game whose tables are read for any the mod has not got.
