Actions

An action is what a trigger does once its conditions hold. These are all of them:

Create Unit with Properties creates units with hit points, energy and other properties set
Defeat the player loses
Display Text Message shows text on the player's screen
Draw the player draws
Give Units to Player hands units at a location to another player
Kill Unit kills every unit of a type a player owns
Kill Unit At Location kills units in a location
Leader Board Control a leaderboard of units owned
Leader Board Control At Location a leaderboard of units owned in a location
Leader Board Greed a leaderboard of ore and gas towards a goal
Leader Board Kills a leaderboard of kills
Leader Board Points a leaderboard of a score
Leader Board Resources a leaderboard of ore or gas
Leaderboard Computer Players whether computer players are on leaderboards
Leaderboard Goal Control a leaderboard of units owned, towards a goal
Leaderboard Goal Control At Location the same, in a location
Leaderboard Goal Kills a leaderboard of kills, towards a goal
Leaderboard Goal Points a leaderboard of a score, towards a goal
Leaderboard Goal Resources a leaderboard of ore or gas, towards a goal
Minimap Ping pings a location on the player's minimap

Modify Unit Hanger Count adds interceptors or scarabs

Mute Unit Speech silences unit voices

Actions are carried out in order, for the player the trigger is running for. Actions that act on "the player" — showing text, moving the screen, winning — act on that player.

Center View#

Moves the player's screen so the location is in the middle of it. In a single-player game the screen scrolls there and the trigger is held, like a Wait, until it arrives; in a multiplayer game it jumps at once. It does nothing for a computer player, while the game is paused, or with no location.

Action 10 · Center View(Location);

Argument Takes Stored in the action
Location a location (Anywhere is location 64) bytes 0–3 
Center View("Base");

Comment#

Does nothing in the game. Editors show the text as the trigger's name in the trigger list, which is what it is for.

Action 47 · Comment(Text);

Argument Takes Stored in the action
Text text, stored as a string-table entry bytes 4–7 
Comment("Wave 3 spawns");

Create Unit#

Creates the number of units of the type for the player, at the middle of the location. A unit that does not fit there is placed at the nearest spot it fits, up to 128 pixels away; a unit with no room that close is not created. A building is not moved: it is not created on ground it cannot stand on, or where something is in the way. Mineral fields and geysers are always created for Player 12. A count of 0 creates one unit, although the text form writes it as All.

Not every unit can be created:

  • Only Players 1 to 8. Create Unit makes nothing for Players 9 to 12 or None, and with All Players it makes units only for Players 1 to 8. (Run in 1.16.1 and found playing Remastered.)
  • Not a class. Any unit, Men, Buildings and Factories make nothing; it needs a unit type.
  • Only the types StarEdit's unit palette offers. With the game's own unit data that is 168 of the 228 types. The rest make nothing: larvae, eggs and cocoons, the tank and Goliath turrets, interceptors, scarabs, the nuclear missile, Scanner Sweep, Disruption Web, Dark Swarm, the doors and traps, start locations, the race markers, the minerals and gas a worker carries, the four heroes Arcturus Mengsk (Battlecruiser), Aldaris, Raszagal and Gerard DuGalle, and the unused types. (Measured in 1.16.1; Remastered's code makes the same check.)
  • A Map Revealer is created and at once removed as unplaceable in 1.16.1. Remastered keeps it. (Found playing Remastered.)

The scmJS Trigger Editor's unit list for Create Unit shows only the types that can be created, once the game data is installed.

The action has a properties field, bytes 20–23, like Create Unit with Properties. The game reads it for Create Unit too: a value from 1 to 64 creates the units with that properties slot. Editors write 0 there.

Action 44 · Create Unit(Player, Unit, Count, Location);

Argument Takes Stored in the action
Player a player or group bytes 16–19
Unit a unit type a trigger can make; the unit classes make nothing bytes 24–25
Count a number of units, 1 to 255 (0 makes one) byte 27
Location a location (Anywhere is location 64) bytes 0–3 
Create Unit("Player 8", "Zerg Zergling", 6, "Spawn");

Create Unit with Properties#

As Create Unit, and the new units take the properties of one of the map's 64 unit properties slots: hit points, shields and energy as percentages, resources, hangar count, and states such as cloaked, burrowed, lifted or hallucinated. The slots are stored in the map's UPRP section; the editor's Triggers ▸ Unit Properties Slots… edits them. A unit is created cloaked or burrowed only if its owner has the technology that lets it, and resources are kept to 16 bits. It can create the same units, for the same players, as Create Unit.

Action 11 · Create Unit with Properties(Player, Unit, Count, Location, Properties);

Argument Takes Stored in the action
Player a player or group bytes 16–19
Unit a unit type a trigger can make; the unit classes make nothing bytes 24–25
Count a number of units, 1 to 255 (0 makes one) byte 27
Location a location (Anywhere is location 64) bytes 0–3
Properties a unit properties slot bytes 20–23 
Create Unit with Properties("Player 8", "Zerg Hydralisk", 4, "Spawn", 1);

Defeat#

The player loses. Nobody else is affected. In a Use Map Settings game the player's units stay on the map, idle, and the player stops running triggers and drops out of every group. A Defeat that comes after a Victory for the same player in the same pass waits, and so never takes effect. See Winning and losing.

Action 2 · Defeat();

It takes no arguments.

Defeat();

Display Text Message#

Shows the text on the player's screen. Always Display shows it even to a player who has turned subtitles off; Don't Always Display follows that setting. The text can carry the game's colour codes. Only the player the trigger runs for sees it: a computer player's Display Text shows on nobody's screen. The text stays for 4 seconds, or 50 milliseconds for each character of a longer text, in real time.

Action 9 · Display Text Message(Display, Text);

Argument Takes Stored in the action
Display Always Display or Don't Always Display bit 0x04 of byte 28
Text text, stored as a string-table entry bytes 4–7 
Display Text Message(Always Display, "Defend the base until help arrives.");

Draw#

Gives the player a draw. It is a draw for everyone only when every player in the game draws or wins in the same pass; otherwise every other player still in the game with no result is defeated. See Winning and losing.

Action 56 · Draw();

It takes no arguments.

Draw();

Give Units to Player#

Hands the number of units of the type in the location from one player to another. With a group as the player, the count is for the whole group. A transport takes its cargo along to the new owner; a unit inside a transport is not given on its own.

Action 48 · Give Units to Player(From, To, Unit, Count, Location);

Argument Takes Stored in the action
From a player or group bytes 16–19
To a player or group bytes 20–23
Unit a unit type, or one of the unit classes bytes 24–25
Count a number of units, 1 to 255, or All (stored as 0) byte 27
Location a location (Anywhere is location 64) bytes 0–3 
Give Units to Player("Player 12", "Current Player", "Any unit", All, "Rescue");

Kill Unit#

Kills every unit of the type the player owns, anywhere on the map, with their death animation. A unit killed this way adds nothing to anyone's death count, kills or score: only a unit that dies in the game, shot or killed by a spell, does. A death counter meant to see a unit die therefore never sees Kill Unit. Any unit means every unit the player owns, mineral fields included.

Action 22 · Kill Unit(Player, Unit);

Argument Takes Stored in the action
Player a player or group bytes 16–19
Unit a unit type, or one of the unit classes bytes 24–25 
Kill Unit("Player 8", "Zerg Larva");

Kill Unit At Location#

Move Location#

Centres the second location (Move) on a unit of the type owned by the player inside the first (Unit at). Following a unit with a location, so that other triggers can act around it, is done with this. With no such unit, the second location is centred on the first. The moved location keeps its size and is kept inside the map. Anywhere can be moved too.

Argument Takes Stored in the action

Move Location("Current Player", "Terran Marine", "Anywhere", "Hero");

Pause Game#

Pauses the game. It works in single player only, and only for a person's trigger; in a multiplayer game it does nothing. The triggers keep running while the game is paused: waits count down and passes go on, but the game clock and the countdown stop. The game is unpaused when the trigger that paused it finishes.

Action 5 · Pause Game();

It takes no arguments.

Pause Game();

Pause Timer#

Stops the countdown timer where it is.

Action 54 · Pause Timer();

It takes no arguments.

Pause Timer();

Play WAV#

Plays a sound for the player. The file is one stored in the map archive, which the editor's Sound Editor adds, or one of the game's own sounds by its path, such as sound\Terran\Marine\TMaYes00.wav. A sound of the game's needs no file in the map; the Trigger Editor's Browse… lists them. Duration is the sound's length in milliseconds, which editors fill in from the file. The game does not use it: Play WAV never holds the trigger, so the next action runs while the sound plays. Only the player the trigger runs for hears it.

Action 8 · Play WAV(WAV, Duration);

Argument Takes Stored in the action
WAV the name of a sound file in the map, stored as a string-table entry bytes 8–11
Duration a time in milliseconds bytes 12–15 
Play WAV("staredit\\wav\\alarm.wav", 1500);

Preserve Trigger#

Keeps the trigger after it runs, so it runs again on every cycle its conditions hold. Without it a trigger runs once for each player it runs for. The trigger's Preserved flag (0x04) does the same.

Action 3 · Preserve Trigger();

It takes no arguments.

Preserve Trigger();

Run AI Script#

Starts an AI script for the player, which is normally a computer player: the custom-level scripts that make it play a normal game, or one of the small scripts that change its behaviour. For anyone but a computer player (a person, a rescuable slot or a neutral slot) the game runs only the scripts that make sense for them: the bunker, transport and web scripts (EnBk, EnTr, ExTr, DWHe, PB3F) and the shared-vision ones (+Vi and −Vi), and for a neutral slot also Rscu. It ignores any other.

Action 15 · Run AI Script(Script);

Argument Takes Stored in the action
Script an AI script, stored as its four-letter code bytes 20–23 
Run AI Script("Terran Expansion Custom Level");

Run AI Script At Location#

As Run AI Script, for the scripts that act on a place, such as Value This Area Higher or Make These Units Patrol.

Action 16 · Run AI Script At Location(Script, Location);

Argument Takes Stored in the action
Script an AI script, stored as its four-letter code bytes 20–23
Location a location (Anywhere is location 64) bytes 0–3 
Run AI Script At Location("Value This Area Higher", "Expansion");

Set Alliance Status#

Sets how the player the trigger runs for stands towards the Player argument: enemy, ally, or ally for victory. Any status value other than ally and allied victory makes them enemies.

Set Deaths#

Changes the player's death count for the unit type. It is how maps keep numbers: nothing but Set Deaths and units dying in the game changes a death count, so the counts of unit types a map never uses can hold anything.

Add past 4,294,967,295 wraps around to 0, and Subtract stops at 0. It writes nothing for a player above Player 8 or a unit number above 232, so in 1.16.1 it cannot reach memory outside the table (see EUD). Remastered is the same unless the map uses EUD triggers.

The unit classes do not work as counters. Set Deaths of Any unit writes nothing. Men, Buildings and Factories change the player's real counts of those lost, the ones the game adds to whenever such a unit dies, so a number kept there is mixed with real deaths (see Deaths and kills).

Transmission#

A message from a unit: the unit type's portrait talks, the text is shown and the sound plays. The first unit of the type in the location, whoever owns it, blinks and is pinged on the minimap; with none there, nothing is pinged. Like a Wait, it holds the rest of the trigger until it is over, in the player's wait slot. How long that is starts from the sound's length (WAV duration) and is changed by the modifier and Duration: Set To replaces it, Add and Subtract change it.

In a single-player game it holds until the portrait has finished talking; in a multiplayer game for that time, in milliseconds of game speed. For a computer player it shows nothing and holds nothing, and without a location it does nothing at all.
