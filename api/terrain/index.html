isomTypes

hasIsom

hasIsom(): boolean;

Whether the open map carries an ISOM section the isometric brush can work on.

checkIsom

checkIsom(): Promise<IsomReport | null>;

How well the ISOM describes the tiles, and what rebuilding it would do about that: rects measured, mismatched among them, inherent of those a rebuild would leave behind (terrain no lattice describes — hand-placed tiles, blends, another editor's ground), and stale when a rebuild would bring more than the palette's threshold back in step. Null when the map has no ISOM (hasIsom) or no map is open. Waits for the tileset graphics to load and rejects when they are missing.

Offer tx.rebuildIsom on stale, not on mismatched: the two measure opposite directions, a rebuild converges in one pass, and inherent never goes away.

const r = await api.terrain.checkIsom();
if (r?.stale) api.document.edit("Rebuild ISOM", (tx) => { tx.rebuildIsom(); });
Try it

terrainAt

terrainAt(tx: number, ty: number): number | null;

The terrain a tile belongs to, as the id types() lists (a flat pair's CV5 index): the tile's own group when it is flat ground, else — under a cliff, a shore or a doodad — what the ISOM lattice says the diamond there is. Null off the map, without the tileset graphics, or when neither tells.

symmetryShares

symmetryShares(): Partial<Record<SymmetryMode, number>>;

How alike the map's ground plays to its own image under each symmetry mode that fits its shape, 0..1: the share of small squares (minitiles) that walk, stand and build as their images do. A mirrored map reads 0.98 and up under its own mode. Empty without the graphics.

fairness

fairness(mode?: SymmetryMode): FairnessReport | null;

The map against its own image under mode (the symmetry tool's mode when omitted): how many small squares differ in walking, height and building, the places they are in, a mask for drawing them, and the mineral fields, geysers and start locations with no equal counterpart. Null for "none", for a mode the map's shape does not allow, and without the graphics.

const report = api.terrain.fairness("h");
if (report) api.ui.status(`${report.unlike} small squares differ in ${report.places.length} places`);

pieces

pieces(): TerrainPiece[];

The list the Tile palette's Pieces view shows for the map in front, unfiltered: the sets plugins provide for its tileset first, then the pieces cut from the map and from what was learned from folders of maps, the same tiles listed once. A cut piece with the same tiles as a provided one is left out. The learned part is read the first time it is asked for, and the "pieces" event fires when it arrives. cutPieces

cutPieces(maps: readonly PieceMap[]): TerrainPiece[];

The pieces the rule cuts from maps of your own (each { tiles, width, height }), read against the tileset of the map in front — to mine a folder and keep the result where you like. The same tiles are folded into one piece when the graphics are loaded. Nothing is kept by the editor.

// Maps read with @scm-js/core's openMapBytes, bundled into the plugin.
import { openMapBytes } from "@scm-js/core";
const files = await api.ui.pickFiles({ directory: true });
const maps = [];
for (const f of files.filter((f) => /\.sc[mx]$/i.test(f.path))) {
  const opened = await openMapBytes(new Uint8Array(await f.file.arrayBuffer()), f.path).catch(() => null);
  if (opened) maps.push(opened.scenario);
}
api.log(api.terrain.cutPieces(maps).length, "pieces");

});

borrowed

borrowed(options?: { scan?: boolean; }): Promise<BorrowedTerrainInfo[]>;

The terrains of other tilesets the open map's tileset can lay (its Isometric tab's "From other tilesets"): those whose every tile, and every tile of the ground the brush lays them onto, has a copy here. Found by matching pictures, once per pair of tilesets' files, or given by a plugin (provideBorrowTable). Resolves after reading what was found before and the other tilesets' files, so tx.paintBorrowed can run; with scan: true, works it out first where it never was (seconds, once). Empty without the graphics, and when the editor draws from the game's own data (nothing there is borrowed).

for (const b of await api.terrain.borrowed({ scan: true })) api.log(b.source, b.name, b.id);
Try it

provideBorrowTable

provideBorrowTable(spec: BorrowTableSpec): Disposable;

Hand the editor the table for a pair of tilesets: which tile of tileset to write for each tile of source. The editor's own picture match is then not used for that pair: a mod's author knows which copy is meant, under which flags. borrowed() lists what the table makes paintable. Taken back with the plugin, or by disposing.

api.terrain.provideBorrowTable({ id: "install", tileset: "badlands", source: "install", pairs: [[0x30, 0x9a40], [0x31, 0x9a41]] });

Hand the editor the drawn border between a borrowed terrain and a ground of the map's tileset: which tile to lay for each shape of the border. Try it

copies

copies(options?: { scan?: boolean; }): Promise<CopiedTerrainInfo[]>;

The open map's tileset's copied terrains (its Isometric tab's "Copied terrain"): a terrain held again at another height whose edge pieces the tileset holds there too. Found by the editor from the tileset's files (once per files, by itself when the tileset holds a copy), or given (provideCopies, a mod's terrain file). IsomReportinterface

interface IsomReport

checkIsom with what a rebuild would do about it — the verdict the palette, Check Map and the Repair plugin draw from.

The two numbers measure opposite directions and are not inverses: mismatched is the lattice failing to reproduce the tiles, while a rebuild votes a lattice out of the tiles. A rebuild converges in one pass and leaves inherent behind for good, because hand-placed tiles, blends and another editor's ground are not terrain any lattice describes. Reporting mismatched alone therefore recommended a repair that could not move the number, on every map with terrain like that.

inherent: number

Of mismatched, the rects a rebuild would leave: terrain no lattice describes.

stale: boolean

A rebuild would bring more than STALE_ISOM_SHARE of the rects back in step.
