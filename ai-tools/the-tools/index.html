The tools

There are 59. They come in four sets. The map tools are always there; the other three are switched on in the Claude Desktop extension's settings, or with --tools after mcp (--tools mods,account, or --tools all). When a set is off, the AI is told so and can say how to switch it on.

Set Name for --tools Tools How many
Maps always on map_…, editor_…, doctor 40
Mods mods mod_… 8
Replays replays replay_info, replay_map 2
scmjs.dev account account account_…, library_…, share, replay_sync 9

Each but the editor_ tools and account_login is a command of the command line guide, and its arguments are the command's options by name: --dry-run is dryRun, --in is in. A tool answers with the command's text and, beside it, the command's --json data.

Tools What they do Write files

map_triggers_export, map_strings_export The triggers and the strings as text, in the trigger window's text form and as <number><TAB><text> lines No
map_triggers_import, map_strings_import, map_strings_prune The text back into the map, passed inline, and the unused strings dropped Yes
map_units, map_locations The units and the locations as rows: a unit's index, type, player and position, filtered by type, player or area; a location's number, name and bounds No
map_terrain, map_doodads The terrain and the doodads: the tileset's terrains with the tiles each covers and the map as a grid of letters; the doodads placed, and the ones the tileset has No
map_edit A list of edits to units, locations, sprites, fog, terrain and doodads, applied together or not at all Yes
map_settings The players, the forces, and the unit, upgrade and technology settings and switch names the map changes No
map_set The map's name, description and revision, and its players, forces, unit, upgrade and technology settings and switch names Yes
map_script_export, map_script_api The map's TrigScript script as text, with whether the map's triggers are built from it; and what a script can call, looked up by word, with the map's own locations, switches and units by name No
map_script_import Files of the script written into the map, passed inline, and compiled: the errors come back as file:line:column. The map's triggers change only with map_build Yes
map_resize, map_new, map_build, map_run Scenario ▸ Resize, a new map, the TrigScript build, a plugin run over the map Yes
map_generate A symmetric melee map from a seed, walked and checked before it is written Yes
map_optimize The map made smaller Only with write: true
map_preview The map as a picture: the answer is the PNG itself, so a model that can see images sees the map No
map_analyze A melee map's layout: starts, naturals, the walks between starts, their narrowest points and the verdicts; with picture, the PNG too No
map_trace, map_cost, map_coverage The triggers run in the game, what they cost, and which fired across many replays No
map_test Scenarios played on the map: units ordered about and things made to happen at set times, then what held, what was shown, which triggers fired and how the game ended The replay of a scenario that failed; with save, the tests file

replay_info, replay_map What a replay holds, with builds what each player ordered and with mod the mod's names; and the replay's map written out replay_map

A few tools differ from their commands:

  • map_optimize is a dry run unless given write: true or dryRun: false, the other way round from the command.
  • map_find takes kinds and matchCase as well as in and case, map_run takes args as well as arg, and map_preview takes marks as well as units.
  • map_run takes game: false where the command takes --no-game, and map_generate has no rush.
  • map_trace and map_cost take mod, replay, order and every, as the commands take --mod, --replay, --order and --every. With replay, the map's path may be left out.
  • map_test takes the scenarios themselves as scenarios, in the tests file's form, where the command reads them from standard input, and tests files in tests. A scenario given this way may leave expect out, to see what the game does. The answer always lists every expectation with what the game gave, then how the game ended, the lines shown and the triggers that fired; the command prints what failed, and the rest with --show. only takes a list of names where the command takes --only once a name. It has no clips and no update.
  • map_script_export, map_script_import and map_script_api are scmjs map script export, import and api. The tools pass the files' text inline: map_script_import takes files as names with text, and null for a file to remove, where the command reads files and folders and takes --remove. map_script_api takes the map as path and the words as search.
  • map_set takes the settings as arguments (players, forces, units, upgrades, techs, switches), where the command takes a file with --settings.
  • map_edit takes the list itself as edits, where the command takes a file. An edit that cannot be done comes back as an error naming it, such as edits[1] (remove_units): there is no unit 99: the map's units are 0 to 20, and nothing is written.
  • mod_play waits wait seconds for the page, 300 by default.
  • share, replay_sync, library_unlink and library_remove take confirm on a second call where the commands take --yes or ask on the terminal. account_info is scmjs account, library_set is library rename and library note together, and library_remove is library rm. share takes link: false for --no-link, and has no --copy or --qr. replay_sync takes no --watch or --link.
  • The tools answer in English whatever the language of the commands, since the model reads them.

The rest of the commands are not tools: map test, map rush, map heatmap, map log, map blame, map merge, map unpack and pack, map sounds, map fetch, map share and replay share (share does both), logout (account_login is the browser sign-in; login --device is not a tool), replay sync --watch, replay watch and export, the bot and plugin commands, and init. An AI app that can run commands in a terminal, as Claude Code can, runs those as you would.
