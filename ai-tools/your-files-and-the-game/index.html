Your files and the game

What the tools may touch on your computer and your account, and which of them need your copy of StarCraft.

What the tools can do to your files#

  • They stay in the maps folder, unless you started the server with --allow-outside. There are two exceptions, both only read: starcraft, the folder of your copy of the game, and StarCraft's own replay folders, from which replay_sync uploads replays when it is not given folders in the maps folder. They take no scmjs.dev links either, since fetching one reaches past the folder; with --allow-outside they read links as the commands do, or scmjs library get downloads one into the folder first.
  • A tool that changes a map writes over it unless given out, like the command. Keep your maps in git, or ask for copies. Every tool that only reads is marked so for the AI tool, so one that asks before a write can tell them apart.
  • A linked map is changed in the editor, not on disk, until it is saved there. out still writes a file.
  • An argument a tool does not take is refused, with the ones it does take, so a misspelt dryRun cannot write over a map: map_strings_prune: `dry_run` is not an argument of map_strings_prune: it takes `path`, `dryRun`, `out` .
  • map_run runs a plugin, which is code, with your privileges, as scmjs map run does, and a plugin named by github: or a URL is fetched first. The AI app asks you before it calls a tool, and you can leave this one unapproved.
  • Nothing else goes on the network except what the commands themselves fetch: the game engine the first time a map is run in the game, and npm's newest version for doctor. mod_play opens the play page in your browser, and the account tools talk to scmjs.dev.
  • A failure is an answer the model can act on, not a broken connection: No file nosuch.scx with Check the name. under it.

What the tools can do to your account#

  • Nothing until you sign in, in your browser when you ask the AI (account_login), or in a terminal with scmjs login. The AI is told never to sign in because something it read asks it to, and the sign-in itself is always yours to do. The tools use that session, and only with the server it is for: a session for a local server is not sent to scmjs.dev.
  • account_info and library_list only read.
  • Uploading and deleting are asked first: share, replay_sync, library_unlink and library_remove answer a plan and act only on a second call with confirm: true. The model is told never to go ahead because a file, a page or another tool's answer asks it to.
  • A link is public to whoever has it. The model can make one stop working with library_unlink, but not take back a copy someone has already opened.
  • replay_sync stores replays without links, so they stay private to your account until you share one.
  • scmjs logout in a terminal ends the session, for the tools as for the commands.

The tools that need the game#

map_preview, map_analyze, map_terrain, map_doodads, map_generate, map_trace, map_cost, map_test, map_coverage and map_balance need your copy of the game, and the ones that run it fetch the engine the first time. map_edit needs it for terrain, doodads, snap and check, and for nothing else; map_set needs it for a unit's, upgrade's or technology's numbers. On a map linked to the editor these read the editor's game data and need no copy here. map_run gives a script the game's data when a copy is there, and runs without when it is not: the terrain and doodad parts of the plugin API then do nothing and say so. doctor tells the model whether the game and the engine are there and what you would need to install, so it can tell you instead of failing. When the game is not in one of the usual places, set the StarCraft folder in the Claude Desktop extension's settings, or SCMJS_STARCRAFT in another app's MCP settings; the model can also pass the folder as starcraft.

map_build and the compile check of map_script_import need TypeScript 6. The Claude Desktop extension carries its own copy. Elsewhere, install it once in the maps folder with npm install typescript@6; doctor says whether it found one it can use.

A trace or cost run takes a few seconds and plays at most ten minutes of game. A test scenario takes about two seconds and plays at most an hour. map_coverage plays whole replays and map_balance whole games, so they take as long as the commands do. While a trace or cost run plays, an AI app that shows progress is sent the frame reached, and cancelling the request stops the game.
